# Asset Mapping

## Resource Root

All Android resources live under `app/src/main/res/`. The tree mirrors the vanilla
APK's resource layout: identical file names/paths so the reconstruction stays
visually and structurally faithful (source: `C:\Repositories\Idle Guild
Master\reference\clean_apk\res`).

```text
res/
├── anim/ animator/ interpolator/      Animation definitions
├── color/ color-night/ color-v31/     Color resources + variants
├── drawable/ drawable-hdpi/ drawable-watch/  Drawables, icons, XML shapes, 9-patch
├── layout/ layout-land/ layout-ldrtl/ layout-sw600dp/ layout-v26/ layout-watch/
│   └── ...                            Activity/fragment/dialog/item layouts (DataBinding <layout> roots)
├── menu/                              App drawer/options menus
├── mipmap-*/ mipmap-anydpi-v26/       Launcher icons (legacy)
├── navigation/                        Navigation resources
├── raw/                               Raw bundled binaries (play-services metadata files)
├── values/ values-af/ values-am/ ...  Strings, colors, styles, dimens; ~130 locale folders
└── xml/                               XML resources: file_paths.xml, splits0.xml,
                                       billing/ad-sdk metadata (com_android_billingclient_*)
```

`app/src/main/assets/` (non-Android assets):

```text
assets/
├── manual_load.txt   Real example save (JSON) — test fixture used by
│                     DebugToggles.LOAD_FROM_TEST_FILE
└── dexopt/           Marker directory (keeps dexopt disabled for assets)
```

## Naming Conventions (observed in the codebase)

| Prefix        | Purpose                                            | Example                       |
| ------------- | -------------------------------------------------- | ----------------------------- |
| `area_*`      | Area detail artwork (dungeon/raid screen image)    | `area_enchanted_forest`       |
| `summary_*`   | Area summary card artwork                          | `summary_enchanted_forest`    |
| `dungeon_name_*` / `log_*` | Area names and combat log strings      | `dungeon_name_enchanted_forest`, `log_enchanted_forest_enter` |
| `type_*`      | Weapon/armor type names (bow, dagger, staff, ...)  | `type_bow`, `type_staff`      |
| `unit_*`      | Entity/unit artwork (enemies, adventurer classes)  | `unit_balrog`                 |
| `layout_*` / `dialog_*` / `fragment_*` | Layouts per binding class      | `layout_dungeon`, `dialog_shop`, `fragment_headquarters` |

Strings follow semantic keys: many are injected with `String.format` placeholders
(`getString(R.string.headquarters_quarters_description_short)` etc.).

## Generated `R` and DataBinding Classes

The Kotlin code references `R.string.*`, `R.drawable.*`, `R.color.*`, `R.id.*` and
generated binding classes (`ActivityMainBinding`, `FragmentDungeonsBinding`,
`LayoutDungeonBinding`, `DialogShopBinding`, ...). These are **generated by the
build** from `res/` XML:

- `R` is produced by the Android resource compiler (`android.nonTransitiveRClass`
  is false → a single package-level `R` merges app + library resources).
- Each DataBinding layout XML (root `<layout>`) generates a `*Binding` class;
  fragments access views through `binding.<viewId>`.

> **Rule**: edit the XML in `res/`, never the generated classes in `app/build/`.

## Resource Resolution Order

Android resolves resources by configuration qualifiers. The repo intentionally keeps
the vanilla's wide set of qualifiers (screen size, orientation, night mode, RTL,
~130 locales). Mod gameplay strings go into `values/strings.xml` **and** every
`values-<locale>/strings.xml` that mirrors them, so translations stay consistent.

## Mod-Specific Assets

Mod branding touches a few resources only:

- `values*/strings.xml` — `app_name` = "IGM Modded"
- `AndroidManifest.xml` — launcher icon `@drawable/unit_balrog` (a game entity
  drawable reused as the mod icon) for both `icon` and `roundIcon`
- `mipmap-anydpi-v26/ic_launcher.xml` — legacy launcher config retained

## Adding a New Asset

1. Put the file in the correct `res/<type>[-qualifiers]/` folder (drawable → images,
   layout → XML layouts, string → `values*/strings.xml`, ...).
2. Use the project's naming convention (table above) so it finds a clear home.
3. Reference it from Kotlin via the generated `R.*` constant after a build.
4. If it is a *generated asset* (e.g. output of a converter), keep the generator in
   `scripts/` and the artifact gitignored — do not commit derived assets unless
   intentionally version-controlled (see `.agents/AGENTS.md`).
